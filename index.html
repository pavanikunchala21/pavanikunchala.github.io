Selected Projects — Detailed case studies (STAR)

E-Commerce Backend System

Problem solved: Reliable catalog, cart & order microservices for a medium-size online shop
Repo
STAR Case Study

Situation: A local retailer wanted to scale online sales with a modular backend that could handle concurrent orders and inventory updates without conflicts.

Task: Design and implement a microservice-based backend: Product, Cart, Order, and Auth services with reliable data consistency and REST API contracts for front-end consumption.

Action: I designed DB schemas (MySQL) and used Spring Boot services for each bounded context. Implemented optimistic locking for inventory updates, event-driven order processing (using simple message queue pattern / local queue), transactional boundaries via Spring transactions, and JWT-based authentication. Wrote integration tests (MockMVC + Testcontainers for MySQL) and created OpenAPI docs for the APIs.

Result: The system supported 500 concurrent checkouts in load tests with zero inventory inconsistencies. Response times during peak load remained within SLA (p95 < 320ms). The client could onboard new storefront frontends easily using the provided REST contracts.

Key highlights / Docs
  • Design artifacts: ER diagram, service boundaries, API contract (OpenAPI)
  • Tech: C, Java, Spring Boot, REST APIs, SQL, Docker (optional for deploy)
  • Production-ready features: Optimistic locking, pagination, filtering, health checks

Real-Time Chart Application

Problem solved: Live metric streaming for dashboards and alerts
Repo
STAR Case Study

Situation: A product manager needed a live view of system metrics (requests/sec, errors, latency) to make operational decisions.

Task: Build backend endpoints and a streaming interface that feeds the frontend charts in near real-time with minimal latency.

Action: Implemented a Spring Boot service exposing WebSocket endpoints and REST fallback. Backend collected metrics from simulated event producers and streamed aggregated values over WebSockets; added batching and compression to reduce bandwidth. Authenticated WebSocket sessions and provided reconnect logic on the client side. Added an API to query historical windows for charts.

Result: Frontend charts displayed updates in <200ms after metric ingestion on average. The streaming approach reduced REST polling overhead by 92% and allowed quicker troubleshooting.

Key highlights / Docs
  • Tech: Java, Spring Boot, WebSocket, REST, SQL
  • Features: Aggregation pipeline, authentication, reconnect logic, historical queries

Customer Support Ticket Analysis Dashboard

Problem solved: Automate insights from support tickets for trend detection and SLA monitoring
Repo
STAR Case Study

Situation: Support teams manually reviewed tickets and missed trending issues and repetitive queries that hurt SLA and agent productivity.

Task: Build a pipeline that ingests ticket text, computes trends & sentiment, and exposes aggregated metrics to a dashboard API.

Action: Built a simple ETL pipeline: fetch tickets via API, preprocess text (clean + tokenization), run lightweight sentiment scoring (lexicon-based) and simple clustering for repetitive queries. Stored aggregated metrics in a reporting store and exposed REST APIs for dashboard charts. Added scheduled jobs to compute daily summaries and anomaly alerts.

Result: Team detected top-3 recurring issues automatically; average time-to-resolution dropped by 18% in testing. The dashboard provided daily trending graphs and simple sentiment scoring useful for prioritization.

Key highlights / Docs
  • Tech: Java, Spring Boot, REST APIs, SQL
  • Features: ETL pipeline, scheduled summarization, alerting, REST APIs for visualization
