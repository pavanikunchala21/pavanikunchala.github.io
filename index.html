Latest Projects — Detailed case studies (STAR)

E-Commerce Backend System

Problem solved: Reliable catalog, cart & order microservices for a medium-size online shop
Repo
STAR Case Study

Situation: A local retailer wanted to scale online sales with a modular backend that could handle concurrent orders and inventory updates without conflicts.

Task: Design and implement a microservice-based backend: Product, Cart, Order, and Auth services with reliable data consistency and REST API contracts for front-end consumption.

Action: Designed DB schemas (MySQL) and used Spring Boot services for each bounded context. Implemented optimistic locking for inventory updates, event-driven order processing, transactional boundaries via Spring transactions, and JWT-based authentication. Wrote integration tests and created OpenAPI docs for the APIs.

Result: The system supported 500 concurrent checkouts in load tests with zero inventory inconsistencies. Response times during peak load remained within SLA (p95 < 320ms).

Real-Time Chart Application

Problem solved: Live metric streaming for dashboards and alerts
Repo
STAR Case Study

Situation: A product manager needed a live view of system metrics (requests/sec, errors, latency) to make operational decisions.

Task: Build backend endpoints and a streaming interface that feeds the frontend charts in near real-time with minimal latency.

Action: Implemented a Spring Boot service exposing WebSocket endpoints and REST fallback. Backend collected metrics from simulated event producers and streamed aggregated values over WebSockets; added batching and compression to reduce bandwidth. Authenticated WebSocket sessions and provided reconnect logic on the client side.

Result: Frontend charts displayed updates in <200ms after metric ingestion on average and reduced REST polling overhead significantly.

Customer Support Ticket Analysis Dashboard

Problem solved: Automate insights from support tickets for trend detection and SLA monitoring
Repo
STAR Case Study

Situation: Support teams manually reviewed tickets and missed trending issues and repetitive queries that hurt SLA and agent productivity.

Task: Build a pipeline that ingests ticket text, computes trends & sentiment, and exposes aggregated metrics to a dashboard API.

Action: Built an ETL pipeline: fetch tickets via API, preprocess text (clean + tokenize), run lightweight sentiment scoring and clustering for repetitive queries. Stored aggregated metrics in a reporting store and exposed REST APIs for dashboard charts.

Result: Team detected top-3 recurring issues automatically; average time-to-resolution dropped by 18% in testing.
